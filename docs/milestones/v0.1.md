# v0.1: first test report to first health view

**Goal**: a team can send e2e results from their CI with one command, and see, for each component
and environment, which version was last tested and whether it passed.

## User story

> As a developer, I add one step after my Playwright tests in CI. It sends the CTRF report to
> Kollaudo with the component, environment and version. I open Kollaudo and see a matrix of my
> components and environments, with the latest tested version and its results in each cell.

## In scope

### Server (`apps/server`)

- `docker compose up` starts Kollaudo and PostgreSQL. Migrations run on startup.
- An admin command creates a project and prints an API token:
  `kollaudo-server project create <name>`.
- Endpoints, all under `/v1` except the health check, authenticated with `Authorization: Bearer <token>`:

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/healthz` | liveness, no authentication |
| `POST` | `/v1/test-runs` | ingest a CTRF report with component, environment, version and kind |
| `GET` | `/v1/test-runs` | list runs, filtered by component, environment and version |
| `GET` | `/v1/test-runs/{id}` | one run with its test results |
| `GET` | `/v1/health` | the component × environment matrix for the token's project |
| `GET` | `/v1/openapi.json` | the OpenAPI document |

- Components, environments and versions are created on first use ([ADR 0012](../adr/0012-create-on-first-use.md)).
- The CTRF report is validated. An invalid report is rejected with a clear error listing the
  problems.

### CLI (`packages/cli`, published as `@kollaudo/cli`)

```bash
export KOLLAUDO_URL=https://kollaudo.example.com
export KOLLAUDO_TOKEN=...

kollaudo push ctrf-report.json --component frontend --env staging --version 1.2.0 \
  [--kind e2e] [--commit <sha>] [--branch <name>] [--tag <tag>] [--pull-request <number>]
```

- `--kind` defaults to `e2e`. `--env` is optional: without it the run is build level
  ([ADR 0003](../adr/0003-own-internal-model.md)).
- Exit code `0` when the report is accepted, even if tests failed. Failing the pipeline on test
  results is the job of the test runner, and later of `kollaudo verdict`.
- `kollaudo --help` and `kollaudo push --help` document every option.

### UI (`apps/web`)

- **Health matrix**: rows are components, columns are environments. Each cell shows the latest
  tested version, when it was tested, and passed, failed, skipped and flaky counts.
- **Test run page**: the tests of one run, grouped by suite, with failure messages, retries and a
  flaky marker.
- Uses only the public API ([ADR 0007](../adr/0007-self-hosted-api-first.md)). Login is by pasting
  an API token, stored in the browser.

### Project

- pnpm monorepo as in [ADR 0009](../adr/0009-typescript-monorepo.md), stack as in
  [ADR 0011](../adr/0011-server-stack.md).
- GitHub Actions: lint, typecheck and tests on every pull request.
- A container image published to `ghcr.io/kollaudo/kollaudo` for each release.
- Recipe: Playwright with the CTRF reporter, in GitHub Actions.
- README quick start that works end to end.

## Out of scope for v0.1

- JUnit XML, deployments, verdict API and `kollaudo verdict` (v0.2).
- Bugs, UAT and manual checks (v0.3).
- CDEvents, gate recipes (v0.4).
- Users, roles and single sign-on. Access is per project token only.
- Helm chart.

## Done when

1. `docker compose up`, then `kollaudo-server project create demo` returns a token.
2. `kollaudo push` with a real Playwright CTRF report returns `0` and a link to the run.
3. The health matrix shows the run in the right cell, and the run page shows its tests.
4. Pushing an invalid report fails with a readable error and exit code `1`.
5. The same flow is covered by an automated end-to-end test in CI.
